## 0. 一句话

**评分器是脑,大模型是嘴。**模型只把评分器已经算完的东西讲成人话,一步决策都不给它,
一个数都不让它自己算。这么切,九条硬约束里只有第 2 条真的要谈。

反过来做 —— 把牌面丢给模型让它说该出哪张 —— 会同时踩掉约束 4、5、6、8,
而且棋力多半不如现在这套跑了七个版本的评分器。这条路本页不再讨论。

## 1. 现在这套教练的天花板

教练说的每一句话,都是 AI 选中的那个候选自带的 `reason` 字符串,外面套一层模板:

* 四步框架:`askCoach()`(`index.html` 约 5573 行),`lines.push` 拼出来的
* 失误反馈:`⚠️ 你出 X,更好的是 Y — ${best.reason}`(约 5566 行)
* 局末复盘:按分差取前 3 条,每条一行(约 5697 行)
* `reason` 本身:`'跟小,保留实力'`、`'分对慎出,无保护先探路'` —— 十来个字的短语拼接

这套的好处是「和 AI 同源」这条约束是**结构性成立**的,不是靠自觉。天花板也在这里:

| 缺口 | 具体表现 |
|---|---|
| **只会推,不会答** | 玩家想问「那我出 ♠K 会怎样」,没有任何入口。教练只能单向广播 |
| **说得太干** | `'跟小,保留实力'` 六个字对会打的人够用,对「想学的人」等于没说 —— 为什么现在要保留?保留给谁?不保留会亏什么? |
| **一个说法走天下** | 新手和老手看到同一句。沪语/普通话/英语三档只换术语,不换深度 |
| **复盘是列表不是故事** | 三条孤立的「第 N 墩你出 X 建议 Y」,拼不出「这局你输在哪」 |

**这四条恰好都是语言问题,不是棋力问题。**所以模型接进来的位置是确定的:接在
`reason` 和玩家之间,不接在 `reason` 上游。

## 2. 撞上哪几条硬约束

| # | 约束 | 会不会破 | 怎么办 |
|---|---|---|---|
| 1 | 单文件、零依赖、无构建 | **不破** | `fetch` 是浏览器原生。不引 SDK、不引 CDN,OpenAI 兼容协议手写十几行就够 |
| 2 | 纯前端、无服务端、无账号 | **要谈** | 见下,这是唯一真正的分岔口 |
| 3 | 锁一屏不滚动 | 不破 | 讲解进右栏教练页签,那里本来就可滚 |
| 4 | AI 只看 `viewFor(seat)` | 不破,但要盯 | 证据包必须从 `view` 出发。顺手把 `G` 塞进去就是开天眼,而且一眼看不出来 |
| 5 | AI 绝不自己实现规则 | 不破 | 模型不产出牌,产出的牌也不会被执行 |
| 6 | 教练与 AI 同源 | **要护栏** | 模型改了建议就作废退回模板,见 §6 |
| 7 | 一切折算成「分」 | 不破 | 分照样是评分器算的,模型只念 |
| 8 | 确定性可复现 | 不破,但要划死线 | 模型输出**绝不回写任何游戏状态**;`test/` 与 `contest/` 的路径根本不碰模型 |
| 9 | 术语可切换 | 不破,反而变好 | 沪语/普通话/英语现在是静态 `TERMS` 表,模型天然会换口音 |

### 约束 2:key 放哪儿,这是分岔口

**静态页里放不了 key。**GitHub Pages 上 view-source 就能拿走,一天就被刷干。
这次贴给我的这把也应当视为已经烧掉的 —— 它进过聊天记录,该换。

三条路:

| 方案 | 破不破约束 2 | 代价 |
|---|---|---|
| **A. BYOK**:玩家自己填 key,存 `localStorage` | **不破** | 玩家得有阿里云账号。绝大多数人不会填 → 功能实际覆盖率很低 |
| B. 自建代理:一个 serverless 函数拿着 key | **破** | 从此有服务端、有账单、有滥用风险,「双击 html 就能玩」不再成立 |
| C. A + 一个可填的自定义 base url | 不破 | 默认 BYOK;想给一群人用的自己去架代理,填进去就行。责任在填的人 |

**选 C。**默认整个功能关掉,没 key 时教练就是现在这套模板教练,一个字不少。
模型是**纯增量**,不是替换 —— 这样「打开网页就能打,不注册、不联网」这句话仍然是真的。

**[待测] CORS 是硬门槛。**浏览器直连要求 `compatible-mode/v1/chat/completions`
的预检回 `Access-Control-Allow-Origin` 且放行 `authorization` 头。
**不放行,方案 A 和 C 就一起死,只剩 B。**所以这是第一件要量的事,不是模型选型。

## 3. 三件必须先量的事(在写任何界面代码之前)

```
QWEN_KEY=sk-... node test/probe-llm.js 80fen-test.html qwen-plus,qwen-max,qwen-turbo 6
node test/probe-llm.js 80fen-test.html x 3 --dump   # 只看证据包,不花 token
```

| | 量什么 | 不过会怎样 |
|---|---|---|
| ① | **CORS** 预检回不回 `Allow-Origin` | 不回 → 整个 BYOK 方案作废,回到「要不要为这个功能开服务端」 |
| ② | **模型清单** `GET /models`,这把 token-plan 套餐 key 到底放行哪些 | 想用的不在里面,§7 的选型重来 |
| ③ | **三个率**:改建议率 / 编事实率 / 延迟 | 见 §6、§7 |

题目不是编的:探针用引擎真打几局,截下真实的「轮到你跟牌」局面,
把评分器算好的证据喂进去,只让模型讲解。它敢改建议、敢编牌面,探针记一笔。

**这一步就是「先造尺子」。**[`measurement.md`](measurement.md) 那一页的结论
——「踩过的坑基本都是量错了,不是想错了」—— 在这里同样成立,而且更危险:
模型的输出永远读着像那么回事,不量根本发现不了它在编。

## 4. 接哪四个口

| 口 | 触发 | 延迟预算 | 频次/局 | 模型 | 新能力? |
|---|---|---|---|---|---|
| **讲解** | 点「问教练」,替换四步框架最后那行建议 | 首字 <1.5s,流式 | 5–10 | 快档 | 否,变好 |
| **追问** | 教练页签下加输入框:「为什么不出 ♠K?」 | 首字 <2s | 0–10 | 快档 + 工具调用 | **是,最大的一个** |
| **失误反馈** | 出牌后分差超门槛 | **不挡出牌**,异步流进页签 | 3–8 | 快档 | 否,变好 |
| **局末复盘** | 结算弹窗 | 5–10s 无所谓 | 1 | 大档 | 是 |

两个要点:

* **失误反馈绝不能挡在出牌路径上。**现在它是同步的(`humanPlay` 里算完 gap 就 push)。
  接了模型必须改成:牌照出、`coachNotes` 照记,讲解异步流进页签。
  严格模式那个 `confirm()` 也不能等模型 —— 它拦的是「要不要反悔」,用的还是评分器的分差。
* **「追问」值得单独说。**它是这四个口里唯一一个现在完全做不到的事,而且实现方式已经现成:
  让模型**工具调用**回评分器。玩家问「出 ♠K 会怎样」,模型调
  `coachScoreFollow(view, plays, [♠K])` 拿到真分,再和首选的分比。
  于是回答是**算出来的**,不是编出来的 —— 这才是把大模型接进这个项目的正当理由:
  它当的是自然语言到评分器的翻译层,不是第二个棋手。

  `coachScoreFollow` / `coachScoreLead` 早就在 `ENGINE` 出口里(块① 末尾),不用动引擎。

## 5. 证据包 = 接口契约

**原则:凡是引擎能算的,都算完再喂。模型只负责讲成人话,一个数不许自己推。**

探针里的 `evidence()` 就是这份契约,`--dump` 能直接打出来。形状:

```
局面 / 我的手牌 / 本墩已出 / 义务 / 我有这门吗 / 台面分
当前最大{谁,是队友,稳不稳} / 我是末家
这门在外{还剩几张, 最大的是, 比我手里最大的还大的有几张}
候选[{牌,分,理由}…] / 首选
```

几条踩过的边:

* **不喂内部序号。**`maxUnseenIdx` 回的 `ordIdx` 是个引擎内部整数(比如 `11`)。
  界面现在原样显示成「在外最大约位次 11」,人尚可忍;喂给模型它一定会编成别的东西。
  换成牌名 `♠A` + 张数。
* **「比我最大的还大的有几张」和界面 quiz 考的是同一问**,口径必须共用,
  否则教练嘴上一个数、考你一个数。
* **`adv.ctx` 是刻意收窄的七个字段**(`partnerWinning` / `isLast` / `ptsTable` /
  `curSeat` / `curBoss` / `leadSuit` / `phase`),不是完整的 `X`。剩下的按 `askCoach()`
  的原样从 `view` 重算(`classify(plays[0].cards, t)`、`makeMemory(view)`)。
  **别图省事把 `followCtx` 的完整 `X` 喂出去** —— 那里面有 `reads`、`holdRange`
  这些推断中间量,喂了既没用又给模型编造的素材。
* **一个字都不能来自 `G`。**只从 `view` 出发,约束 4 才守得住。

## 6. 护栏(能不能上线就看这一节)

| 护栏 | 做法 |
|---|---|
| **改建议 → 作废** | 模型输出最后一行必须是 `建议:<牌>`,解析出来逐张比对 `best.cards`,不等就整段丢掉、退回模板。**约束 6 由代码保证,不靠模型自觉** |
| **编事实 → 量出来** | `factCheck()`,扩一份 `test/audit-llm.js`,和 `audit-reason.js` 同一路数:只查「说的和牌面对不对得上」,不评价棋力 |
| **超时 / 断网 / 没 key / 429** | 静默退回模板教练。玩家最多觉得「今天教练话少」,不会看到报错 |
| **绝不回写状态** | 模型输出只进 `G.coachChat`(纯展示)。`G.coachNotes` 的 gap 仍由评分器算 |
| **测试路径不碰模型** | `test/` `contest/` 一次也不调。约束 8 的确定性和比赛的公平性都不受影响 |
| **key 不出本机** | 只存 `localStorage`,只发往玩家自己填的 base url。不做任何遥测 |

**改建议率的验收线是 0,不是「低就行」。**一次都不许。一个会改建议的模型,
等于在产品里塞了第二套标准 —— 那正是约束 6 存在的理由。

## 7. 选哪个模型

先说判据,再说人选。**这是个「严格遵指令 + 中文口语自然」的活,不是推理活** ——
推理已经由评分器做完了。所以:

1. **改建议率 = 0** 一票否决,不管它多聪明
2. **编事实率**越低越好
3. **首字延迟**:互动那三个口的门槛在 1.5s 上下
4. 中文口语(还得能切沪语口音)
5. 单价

**[待测] 建议的起点**(得先看 `GET /models` 到底放行哪些):

| 口 | 起点 | 为什么 |
|---|---|---|
| 讲解 / 追问 / 失误 | **`qwen-plus`** | 快慢与好坏的折中位;追问要工具调用,别用太小的档 |
| 局末复盘 | **`qwen-max`**(或 `qwen3-max`) | 异步,慢一点无所谓;这一口要的是把一局讲成一个故事、提炼一条能带走的原则 |
| 成本压不住时 | `qwen-turbo` / `qwen-flash` | 讲解这口本来就不难 |

**思考档一律关掉**(`enable_thinking:false`)。推理已经做完了,思考在这里是纯延迟浪费;
更麻烦的是思考过程里模型容易自己"重新判断一遍该出哪张",然后把建议改掉 —— 直接踩 §6 第一条。

## 8. 成本量级

一局约 25 墩,四个口合计约 15 次调用:

* 证据包 600–900 token(手牌 25 张 + 3–5 个候选),加 system 约 1.2k 入 / 150 出
* 局末复盘那一次 3–5k 入 / 400 出
* **一局大约 20k 入 / 2.5k 出**

单价对着控制台的价目表自己乘。BYOK 的好处顺带在这:账单不在我们头上。

## 9. 落地顺序

1. **跑探针**,拿 §3 三个答案。CORS 不过就先停下来重新谈约束 2
2. **造尺子**:`test/audit-llm.js`(改建议率 + 编事实率,N 局批量跑)
3. **只做「局末复盘」一个口。**异步、没有延迟压力、失败了玩家无感、价值最高。
   这一口跑顺了,证据包契约和护栏也就验过了
4. 再做 **讲解 + 追问**(追问是新能力,做完这一步产品形态才真的变)
5. **失误反馈放最后。**它在出牌路径上,最容易伤手感

设置面板加一段「教练 · 大模型」:总开关(默认关)、base url、key、模型、
以及一句明写的「key 只存在这台设备的浏览器里」。

## 10. 明确不做

* **不让模型决策。**一次都不。
* **不让模型算牌。**还剩几张、台面几分,全由引擎算完再喂。
* **不做官方代理。**除非哪天愿意正式放弃约束 2,那是另一个产品决定,不是一个功能。
* **不接进比赛。**`contest/` 是给参赛 AI 的隔离环境,和教练没有关系。
* **不做语音、不做完整 i18n。**撞约束 9 和「明确不做的」那一节。

## 11. 这套量具量不到什么

照 [`measurement.md`](measurement.md) 的规矩,先写清楚盲区:

* **事实体检查不出「说得对但没用」。**每句话都对得上牌面,合起来是废话 —— 探针给满分。
* **改建议率查不出「建议对、解释歪」。**最后一行照抄了,上面三句在讲另一件事,查不出来。
* **上面两样只能人读。**所以探针把原文整段打出来,不是只报数。
* **关键词表是白名单式的。**只认「断门 / 末家 / 毙 / 队友稳赢 / 台面 N 分 / 在外 N 张」
  这六类,模型换个说法就绕过去了 —— 和 `audit-reason.js` 一样的老毛病,
  它量的是「已知的那几种编法有没有发生」,不是「有没有编」。
* **没有棋力尺子,也不需要。**模型不碰决策,`ai-h2h` / `cf-*` 那三把尺子的读数
  接不接模型都不会变一个数。哪天读数变了,就说明有人把模型接到决策上去了。
