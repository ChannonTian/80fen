# 量具:三把尺子 + 一把卡尺,以及每一把量不到什么

这个项目里,**「怎么量」比「改什么」更容易出错**。到 v0.7.5 为止,踩过的坑基本都是量错了,
不是想错了。这一页记三把尺子的用法、各自的盲区,以及验证量具本身的两个空跑。

---

## 一、同桌配对自对弈(`test/ai-h2h.js`、`ab.js`)

**做法**:同一批种子打两遍,交换阵营;引擎统一取一份,只把 `aiDiscard` / `aiChooseLead` /
`aiChooseFollow` 按座位分派到新旧两版。打分是以 80 为零点的零和:做闲家 (闲家分−80),做庄家 (80−闲家分)。

**能量到**:一条改动在「双方都是这套 AI」的世界里值多少分。

**量不到**(每一条都吃过亏):

1. **配合类问题**。两边是同一套启发式的变体,它从不带着意图去调王,这类题目根本不会被出出来。
2. **靠对手不最优挣到的分**。对手就是我自己,他会正确地不上当 —— 「逼他花掉一张大牌」
   这类消耗收益在这里恒等于零(v0.7.4 证明这不是量具缺陷,是定理)。
3. **被支配的选择**。「毙牌该用大王还是主A」这种,淹没在噪声里。
4. **一次决策的价值**。它被整局稀释掉了 —— 这是 v0.7.5 那次误判的根源。

**噪声量级**:700 副一批,SE 通常 0.10~0.40,取决于改动触发的频率。
**触发越少的改动 SE 越小**(方差来自被改变的那些局),所以看到「SE 很小」不等于「效果确凿」,
先问它触发了几次。

**必须做的事**:多批 + 逆方差合并。单批下结论至少错过两次(v0.7.1 的 −0.51、v0.7.3 中途的 +0.04)。

## 二、对固定参照(`ab.js A=index.html B=80fen-test.html`)

**做法**:同上,但 A 换成一个**固定的旧版本**(通常是当前正式版)。

**能量到**:整条改动栈相对一个不动的对手值多少 —— 比自对弈更接近「换个人跟你打」。

**量不到**:仍然不是真人。参照版也不会超付、不会漏算,所以「专治人类错误」的改动它同样看不见。

**盲区之外的价值**:自对弈里每条都 ≥0、合起来对固定参照却是 −0.23 —— 这种背离只有这把尺子能看见。
v0.7.4 就是这么发现的。

## 三、定点反事实回放(`test/cf-ruff.js`)

**做法**:自对弈跑到**符合判据的那个决策点**上分叉,每条支路用同一套 AI 打完整局,比最终得分。
配对比较,同一状态出发。

**能量到**:**一次决策**本身值多少分,以及它的收益从哪儿来(可以顺带统计后续毙牌分、
最后一墩归属、整局得分)。这是三把尺子里唯一能回答「为什么」的。

**量不到 / 必须小心**:

* **一次性偏离 ≠ 策略性偏离**。分叉测的是「这一次改,其余照旧」;
  把它变成规则是「每次都改」。v0.7.5 实测两者差一个数量级:
  单次 +1.32~+2.11,做成规则(甚至硬规则)之后聚合 ≈ 0。
* **分层再看一眼**。同一个平均值可能是两群完全不同的样本拼出来的。
  v0.7.5 的优势按「第几次遇到」是 +0.88 / +0.17 / −0.41,按「手上还有几手钢板」是 0 手 −0.05 / 1 手 +1.63。
  不分层就会得出「这条规则值 +1」的错误结论。
* **分母**。A 支路在所有命中点都有样本,C 支路可能只在子集上有 —— 别拿不同分母的均值直接比。

## 四、教练理由的事实体检(`test/audit-reason.js`)

**不是尺子,是卡尺** —— 它不量棋力,只量**话有没有说错**。

**做法**:AI 自己打完整局,每次决策把选中候选的 `reason` 和当时的客观牌面对上。
每条断言都只查理由**字面自称**的那件事:说「断门」就必须真的断这门,说「最后一手」
就必须真是末家,说「垫废牌」就必须真的 0 分且不是主。**不做任何策略判断**。

**为什么单独要一把**:教练页签直接把这句念给玩家听。牌打对了、理由说错了,
棋力指标一分不掉,可信度却是塌的 —— 三把尺子对这类问题的读数**恒等于零**。
v0.7.7 一扫就是四条,最高的一条占比 62.4%。

**必须小心**:正则会误伤。「尝试吃,但后手**或被毙**」被 `/毙/` 判成「我这手是毙」,
那句话本身完全正确。**先把量具的假阳性排掉,再看数字** —— 和三把尺子的空跑是同一件事。

## 验证量具本身:两个空跑

任何跨文件、跨开关的对照,先做这两件事,否则数字不可信:

```bash
# ① 跨文件空跑:正式版复制一份,自己跟自己打 → 必须精确 0.00
cp index.html /tmp/copy.html
AOVER="egSearch=0" BOVER="egSearch=0" node ab.js index.html /tmp/copy.html 300 20000

# ② 全关空跑:把这一版所有新开关关掉 → 必须精确 0.00
#    不是 0.00 就说明有改动没留开关,消融结论全部作废
AOVER="egSearch=0" BOVER="egSearch=0,新开关1=0,新开关2=0,..." \
  node ab.js index.html 80fen-test.html 700 20000
```

这两个空跑在 v0.7.5 救过一次:−0.35 到底是真效果还是跨文件的量具偏差,只有它们能分开。

## 场景库(`test/ai-scenarios.js`)

不是尺子,是**回归网**。每条实战反馈钉一条断言,防止下一轮把已修的问题改回去。

**一条规矩**:凡是「该做 X」的断言,都要配一条「不该做 X」的对照组。
否则下一轮一定会有人(包括我)把正解当 bug 修掉 —— 这条是 v0.5.8 的教训,已经生效过。

## 一份检查清单

改一条 AI 逻辑,按顺序问:

1. 这条改动**触发多少次**?先插桩数一遍,再谈收益。触发 9 次的规则,分数打平不说明任何事
2. 它触发的场合,和**报障发生的场合**是同一批吗?
   (v0.7.3:规则 78% 触发在 0 分墩,而缺陷平均发生在 8.6 分的墩上 —— 两个分布压根不重合)
3. 单次值多少?用**定点反事实**量,并且**分层**看
4. 做成规则之后值多少?用**配对自对弈**量,**多批合并**
5. 对固定参照呢?自对弈 ≥0 而固定参照 <0,说明有东西没量到
6. 空跑两条过了吗?
7. 钉断言了吗?正反各一条
8. 改到了教练看得见的字?跑一遍 `test/audit-reason.js`,16 类断言应全部 0 不符
