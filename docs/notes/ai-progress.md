## 二、产品方定下的原则(做 AI 改动时对照)

1. **问题不是孤立的,一起改、一起测。** 单点小修用同一个 AI 当队友和对手去评估,会被其他毛病掩盖(§7.11 撤回的 B1 结论)。
2. **不能按下东边起西边。** 修一处要同时量它会不会在别处送分(守底计划的整局对照就是为这个)。
3. **牌权的价值 = 拿到牌权之后接下来 n 墩的预期收益**,领出与跟牌口径不同;台面 0 分、不是末家时也不是 0。
   `measure-tempo` 量的是**当前打法下**的值 —— 打法改了要重量(打法 → 量价值 → 按价值改打法 → 再量)。
4. **角色很重要:** 庄家自己负责守底;帮家不替庄家守底,中盘用王 / 级牌帮牌权过渡(钓主 → 帮家抢权 → 打庄家断门 → 交回);
   庄家对守住最后一墩没把握时不埋分。
5. **术语统一用「钓」:** 钓主(普通话)/ 钓王(沪语)。
6. 试玩反馈优先用**牌谱**核实:结算框「复制牌谱」→ `node test/replay-record.js <牌谱.json>` 逐手还原。
   **v0.7.38 起测试版每局自动存本机、测试版自动上传到 Google 收集表/正式版需玩家开启上传**(`docs/upload/README.md`):
   批量牌谱先过 `node test/records-check.js <文件>... --bad`(按种子重发、逐手重放验收,按玩家概况),只取 `by=h` 的手;`replay`(重打)的局另算。

7. **抢末墩靠什么(09-29):** 现实里末墩最可能靠**单张大王**,其次小王,再其次主级数牌,概率随牌的大小加速递减;
   比这差的单张抢末墩不现实 —— 除非大主都没了、自己明确控制局面,或者用对子 / 甩牌抢底。王要留到最后。
8. **非级数牌的主 A 不算「大牌」(09-29):** 上面压着 12 张,钓主墩 0 分时用它(或副级数牌)拿牌权成本很低、几乎是常规操作。
   接钓主出主 K 几乎不合理(被 A / 级牌连分带牌权拿走),出 A 较合理;要不要接还看手里还剩什么、底分、差多少分过线。
9. **第 2 家毙牌用哪张(09-29),先看第 3、4 家这门断不断:** #3 极高概率不断 → 主分牌可以毙;#3 断、#4 不断 → 主分牌毙是纯送,
   要用**盖过在外主分牌**的一张;两家都断 → 看队友实力:贴副花分 / 氽废牌 / 同样盖过主分。(实现 `ruff2Plan` 整局略负,默认关,待 `survP` 接上再量。)
10. **第 2 家跟分(09-30):** 要判断「队友的大牌不仅盖过 #1、还能盖过 #3」。条件不在我是不是分、Q 是不是暂大,
    而在这门还有什么大、谁有什么、谁断哪门 —— **谁做庄影响很大**(#3 做庄多半断门 → 不加;#4 做庄多半断门 → 加 10;
    #1 做庄不确定 → 不加;都不是庄、牌好 / 我做庄 → 加 5 作可承担的风险)。「有机会领大牌却没领 → 多半没有」是有效信号(已量证)。(实现 `feedPlan`,v0.7.39 开)
11. **藏钢板分牌(09-30):** 第一墩队友 AA 稳赢、我 KK+99,会藏 KK 出 99 —— KK 是本门最大、分没丢,还能盖对手后来领的对子。
    AI 现在把「贴给稳赢队友的分」当落袋、把留着的钢板分牌当负债,这里差距很大(待做)。
12. **真人牌谱来自几位试玩玩家,不是产品方本人**,别默认是产品方打的;样本小的时候先不分析。

## 三、做法(每一条都踩过坑)

- **开关约定:** 新行为一律进 `AIP`,`0` = 旧行为。先做**零点对照**:开关关着时 `ai-h2h` 新旧两边行为不同的种子必须是 0。

  用 `node test/pool-h2h.js <目录> <前缀>` 逆方差合并。**级/局是主指标**,分/局次之。单批不下结论。
- **长实验用 `test/queue.sh`**:断点续跑、4 路并行;跑之前把要测的 html **复制成快照**,队列读快照,代码可以接着改。
  容器会被回收,结果文件放在 scratchpad 里,跑完的结论要当场写进文档。
- **先诊断再改:** 先写一把尺子把问题量出来(估计 vs 实际、按局面分层),再动打分;改完用同一把尺子复量。
  本轮的尺子:`audit-guard`(守底)、`fit-guard`(守底概率拟合)、`diag-third`(第 3 家逐候选 + 末家真应)、

- **「估计准了」≠「选择变了」:** `lastRuffWill` 把校准偏差从 7 降到 2,却只改了约 5% 的种子;
  `trumpTakeAll` 那次是**候选集里压根没有正确的那一手**。估计、候选集、打分三处要分开查。
- 推送前:`node test/check-sync.js --full`(自测 + 文档同步)、浏览器打开无报错(playwright,见 §12)。
