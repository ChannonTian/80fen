## 二、产品方定下的原则(做 AI 改动时对照)

1. **问题不是孤立的,一起改、一起测。** 单点小修用同一个 AI 当队友和对手去评估,会被其他毛病掩盖(§7.11 撤回的 B1 结论)。
2. **不能按下东边起西边。** 修一处要同时量它会不会在别处送分(守底计划的整局对照就是为这个)。
3. **牌权的价值 = 拿到牌权之后接下来 n 墩的预期收益**,领出与跟牌口径不同;台面 0 分、不是末家时也不是 0。
   `measure-tempo` 量的是**当前打法下**的值 —— 打法改了要重量(打法 → 量价值 → 按价值改打法 → 再量)。
4. **角色很重要:** 庄家自己负责守底;帮家不替庄家守底,中盘用王 / 级牌帮牌权过渡(钓主 → 帮家抢权 → 打庄家断门 → 交回);
   庄家对守住最后一墩没把握时不埋分。
5. **术语统一用「钓」:** 钓主(普通话)/ 钓王(沪语)。
6. 试玩反馈优先用**牌谱**核实:结算框「复制牌谱」→ `node test/replay-record.js <牌谱.json>` 逐手还原。

## 三、做法(每一条都踩过坑)

- **开关约定:** 新行为一律进 `AIP`,`0` = 旧行为。先做**零点对照**:开关关着时 `ai-h2h` 新旧两边行为不同的种子必须是 0。

  用 `node test/pool-h2h.js <目录> <前缀>` 逆方差合并。**级/局是主指标**,分/局次之。单批不下结论。
- **长实验用 `test/queue.sh`**:断点续跑、4 路并行;跑之前把要测的 html **复制成快照**,队列读快照,代码可以接着改。
  容器会被回收,结果文件放在 scratchpad 里,跑完的结论要当场写进文档。
- **先诊断再改:** 先写一把尺子把问题量出来(估计 vs 实际、按局面分层),再动打分;改完用同一把尺子复量。

- **「估计准了」≠「选择变了」:** `lastRuffWill` 把校准偏差从 7 降到 2,却只改了约 5% 的种子;
  `trumpTakeAll` 那次是**候选集里压根没有正确的那一手**。估计、候选集、打分三处要分开查。

在现有打分器上继续加项 / 调系数,收益已经很小。能继续往前走的两条路:
① **真实牌谱**(`replay-record.js` 逐手还原)—— 直接看人赢在哪一步;
② **中盘也做「候选 × 抽样手牌 × 续打」的一步前瞻**(现在只有收官 ≤8 张有搜索):即使续打仍用现在的 AI,
   对每个候选各抽几份与推断一致的对手手牌、打到底取平均再挑最好的,理论上**不会比续打策略本身差**(rollout 改进),
   而且对「这一手」逐局面挑,不像改打分式那样一改全改。代价是算力:浏览器里每手可能要数秒,需要只在关键决策点开。

**2026-09-28 产品方:第 3 家接钓主「接多高」的判断框架**(针对教练线标的场景 2b / 2d):
