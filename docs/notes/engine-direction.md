# 引擎方向评估与二代路线(2026-11-11)

产品方问:当前 AI 引擎的开发方向对不对(「方法太简陋」)。对就给后续改进,不对就开新分支新做。

## 一、结论

**地基对、而且强;往上加东西的方式不对。** 不推倒重写,在新分支上换决策核心。

| | 判断 | 处理 |
|---|---|---|
| 规则引擎、候选生成、世界抽样、收官搜索骨架、两把尺子(h2h / pool)、零点对照纪律 | 对 | 留用 |
| 手写一步打分(`scorePlay` / `scoreLeadCore`)当最终裁决 | 到顶 | 降级成候选生成 + 先验 + 兜底 |
| 逐例打补丁(`flagFix` 位掩码、新打分项、新常数) | 投入产出比低 | 停;产品方标记改当回归集 |
| 前半局(13~25 张)没有搜索 | 最大的缺口 | 二代路线第一步补它 |

## 二、证据(都是这次重量或现成记录)

1. **当前引擎在已知对手里最强。** v0.7.66 对联赛第二季冠军 zai-glm(打级,80 种子 × 交换阵营):105 : 55,
   +2.11 ±0.67 / +2.60 ±0.58 级/场(两批),+5.0 分/局。第一季对五份从零写的引擎 94% 胜率。
2. **近七周累计增益是真的,但四成来自一个搜索参数。** v0.7.66 对正式版 AI(v0.7.30),`ai-h2h` 2 × 260 种子:
   +2.37 ±0.92 / +2.88 ±0.76 分/局,+0.039 ±0.020 / +0.056 ±0.017 级/局。
   其中收官搜索 8 → 12 张单项 +1.18 ±0.39 分 / +0.019 级(10-01);其余约 35 个版本合计约 +1.5 分/局。
3. **别人改我们的引擎,赚的也是搜索。** zai-glm fork v0.7.14 只动四处(搜索加深、精确收官、世界抽样加权、底牌加权),
   合计 +3.4 ±0.4 级/场(t=7.9)。它试过的打分 / 效用改动全是噪声或负。
4. **手写打分在前半局接近随机。** 中盘领出前几名候选排对 52%,现有分项线性重配权重 51%(11-07,`lead-rank` / `fit-lead`)。
5. **补丁的量级在噪声线上。** 单项多在 ±0.01~0.03 级/局,要上千局才分得清;AIP 开关 279 个,文档约 1 MB。

**结构原因(不是谁做得不好):**
- 一步打分看不到后果,只能靠人把后果写成规则;规则之间互相打架(按下东边起西边)。
- 单手的好坏差几分,牌运的方差几十分。人盯着单局改,改的多半是噪声。
- 续打用自己 → 量出来的是「在自己这种打法下」的值(王留不留就是这么偏的)。
- 搜索停在 12 张,是因为续打又慢又吵,不是因为前半局不需要搜索。

## 三、二代路线:抽样世界 + 学到的价值

**一句话:** 每一手 = 按信念抽 N 个世界,每个候选在每个世界里用**学到的价值函数**估「这局最后闲家拿多少分」,
换成升级效用取平均,显著才改判。手写打分只负责出候选。

为什么是它:
- 价值函数从几十万局的结果里回归,等于把「续打到底」的噪声提前平均掉,所以能用在整局而不只收官。
- 训练时所有人按真实(不看牌)的打法打,价值网络只是**看得见**四家牌 —— 对抽样世界取平均就是正当的一步策略改进,没有「全知搜索」的偏差。
- 推理是几万次乘加,浏览器里毫秒级;训练只要 CPU。
- 同一套数据以后还能出:不看牌的策略网络(快自对弈 → 多轮迭代)、按出牌似然给世界加权(信念)。

| 步 | 做什么 | 过关线 |
|---|---|---|
| **M1**(在做,`ai2/`) | 自对弈 + 定点分叉造数据 → 全知价值网络 → 接进 `endgameSearch`,13~25 张也搜(`AIP.vnet`,默认 0) | 离线排序明显高于手写打分(对照那个 52%);h2h ≥ 4 × 350 种子 级/局为正且 t ≥ 3;pool 不负 |
| M2 | 用 M1 的引擎重新造数据再训一轮(策略迭代);加「不看牌」的学生网络让自对弈变快 | 第二轮对第一轮 h2h 为正 |
| M3 | 信念:用学生网络算「他要是有这手牌会不会这么出」,给抽样世界加权,替换手写读牌信号 | `ORACLE` 差距(全知 81% vs 抽样 68%)收窄;h2h 为正 |
| M4 | 候选放宽(不只是打分器想得到的那几手);扣底、亮主用同一个价值函数评 | 各自 h2h / `vs-builds` 为正 |
| M5 | 进浏览器:权重量化内嵌、Web Worker、教练理由改用抽样统计(「100 个可能的牌局里这手平均多 X 分」) | UI 端到端通过;产品方试玩 |

**产品方标记的手怎么用:** 收成一个回归集,每个版本报「和标记意见一致的比例」。它是验收,不再是补丁来源。
自对弈结论和产品方实战判断相反时仍以产品方为准 —— 先查续打像不像人。

## 四、风险和退路

| 风险 | 怎么发现 | 退路 |
|---|---|---|
| 价值网络精度不够,候选之间的差被误差淹没 | M1 离线排序关 | 加数据 / 改成直接学「成对差」(同一世界两个候选的结果差);再不行用快速续打 + 更多世界 |
| 候选集里没有正确那手 | 标记回归集里「正确手不在候选中」的比例 | M4 放宽候选 |
| 自对弈变强、人看着怪 | 标记回归集 + 试玩 | 以产品方为准;池子里加真人牌谱局面 |
| 数据是「不开收官搜索」的引擎打的,和实战续打不完全一样 | M2 第二轮数据换成带搜索的引擎 | — |
