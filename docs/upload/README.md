  `curl -sL "<UPLOAD_URL>?key=$RECORDS_READ_KEY" > records.jsonl`。没配的话请产品方从表格导出,或让玩家用「导出」发过来。
- **踩过的坑:**
  - 改了 `apps-script.gs` 要粘进 Apps Script **并发「新版本」**(管理部署 → 编辑 → 版本:新版本)。只保存不发版本,线上还是旧脚本;「新建部署」会换一个网址,网页还连着旧网址。
  - 第一版脚本没有「残局」列,牌谱 JSON 在第 17 列。现在的脚本发现表头对不上,会自动把旧行挪到新排法(`migrate_`);下载按内容找 JSON 格,不按列号。

- **验证线上脚本版本不用写数据:** POST 一条 `{"fmt":"80fen-record-2","id":"probe-x","pid":"probe","partial":true,"tricks":[{"plays":[]}]}`,新脚本回 `why:"tricks"`,旧脚本回 `why:"hands"`,两种都不写入表格。

测试版每打完一局,把这一局写成一份 **`80fen-record-2`**。
没打完的局也存,存成**残局**(`partial: true`):
- 从发完牌开始,每收一墩(以及开打、悔牌之后)把进度覆盖写到本机;
- 正常打完,进度就换成完整牌谱;
- 没打完就离开(刷新、关页面、被系统杀掉、重打、用种子开局、重开整场),下一次开局或下次打开页面时,进度会转成一份残局牌谱,和完整的一样存本机、上传。

不区分离开的原因。规则规定的低分 / 少主重发不算残局。

两种牌谱都按下面两条处理:

- **存本机**:浏览器 localStorage,保留最近 300 局。设置 →「牌谱」→「导出全部牌谱」一次导出成一个 `.txt`,一行一局。手机上会直接弹出系统分享。上传不通时就靠这个。
- **自动上传**:测试版默认上传，第一局结算时告知一次，可以当场点「不要上传」，设置里随时能关；正式版默认不传，也不弹提示，玩家可以在设置里自己打开。数据传到一张 Google 表格,由 [`apps-script.gs`](apps-script.gs) 接收,一局一行。传不上的留在本机,下次打完一局或下次打开页面时补传。服务端按 id 去重,重传不会多出一行。

> **网络:** `script.google.com` 在中国大陆打不开。国内玩家传不上,牌谱留在本机,只能用「导出」发过来。
> 以后要换成国内也能稳定访问的接口,网页端只需要改 `UPLOAD_URL` 和返回格式(`{saved,dup,bad}`)。

## 一、部署收集表(产品方做一次,约 5 分钟)

1. 打开 <https://sheets.new> 新建一张 Google 表格,名字随意,比如「80分牌谱」。
2. 菜单 **扩展程序 → Apps Script**,删掉编辑器里的默认代码,把 [`apps-script.gs`](apps-script.gs) 整份粘进去,保存。
3. (可选,AI 线拉数据用)左侧 **项目设置 → 脚本属性 → 添加脚本属性**:名称 `READ_KEY`,值是一串随机字符(30 位以上,**只用字母和数字**,省得在网址里转义)。**这个值不要发到聊天里或提交进仓库。** 脚本每次请求时才读它,改了不用重新部署。浏览器打开 `…/exec?key=<READ_KEY>`:key 对时显示牌谱(还没数据就是空白),key 不对时显示 `ok`。
4. 右上 **部署 → 新建部署**,类型(齿轮)选 **Web 应用**:
   - 执行身份:**我**
   - 谁可以访问:**任何人**

   点「部署」后会要求授权:选自己的账号。如果出现「Google 未验证此应用」,点「高级 → 转至(不安全)」,再点「允许」。
   权限请求应该只有「查看和管理此应用所在的电子表格」。脚本开头的 `@OnlyCurrentDoc` 把授权限定在这一张表;如果请求的是「所有电子表格」,说明那一行没粘上。

   **「任何人」是必须的,风险可控:** 玩家是匿名打开网页的,网页没法替他们登录 Google,所以只能选「任何人」。
   「任何人」能做的只有脚本里写的两件事:
   - POST 一局牌谱:会校验格式,同一个匿名编号每小时最多 120 局,全部加起来每小时最多 2000 局;
   - 带对的 `READ_KEY` 才能 GET 到数据。

   脚本拿不到你别的文件,也看不到你的账号信息。最坏的情况是有人往表里灌假牌谱:`records-check.js` 会把它们筛掉;
   真被灌了,可以「管理部署 → 归档」立刻关掉接口,再重新部署换一个网址。
   **表格本身保持私有,不用改共享设置**:网页应用以你的身份写入,表格分不分享和它无关。
5. 复制得到的 **Web 应用网址**(`https://script.google.com/macros/s/…/exec`)。这个地址可以公开,会写进网页。
   用浏览器打开它,看到 `ok` 就说明部署成功。
6. 把网址填进 `80fen-test.html` 里的 `const UPLOAD_URL=''`(或者交给 Claude 填),提交即可。

**以后改了脚本:** 把新的 `apps-script.gs` 整份粘进去覆盖,保存,然后 部署 → 管理部署 → 铅笔 → 版本选「新版本」→ 部署。网址不变,网页不用改。

表格里多出一个工作表「牌谱」,一局一行。前面几列是概况(玩家、版本、局号、庄家、主、闲家得分、是否重打、托管墩数、悔牌次数、真人出牌手数),最后一列 `JSON` 是完整牌谱。

## 二、AI 线怎么用

```sh
# 下载(需要 READ_KEY;from=行号 只拉新的)
curl -sL "<UPLOAD_URL>?key=<READ_KEY>" > records.jsonl
# 或者:表格里 文件 → 下载 → CSV,只取 JSON 那一列;玩家发来的「导出」文件可以直接用

node test/records-check.js records.jsonl 80fen-records-*.txt --bad   # 逐局验收 + 按玩家概况(多个文件按 id 去重)
node test/replay-record.js records.jsonl --game=3                    # 逐手还原某一局(第几局,或 id 前几位)
```

`records-check.js` 会把每一局完整重放一遍:用种子重新发牌,核对手牌和底牌;逐手检查是否合法;核对每墩赢家、墩分和闲家总分。任何一项对不上就算坏局,不进统计。上传的接口是公开的,用来训练之前**必须先过这一步**。

**挑「真人决定」时注意:**
- 只取 `by` 为 `h` 的那几手。
- `replay: true` 是重打或用种子开的局,人可能已经见过这副牌,要单独算。
- `hint: 1` 是照着教练提示出的,算半个 AI 决定。
- `u: 1` 是悔牌后重出的一手。

## 三、`80fen-record-2` 字段

它是 `80fen-record-1`(「复制牌谱」的旧格式)的超集。牌的写法:`S/H/D/C` 加点数,11~14 = J Q K A;`X15` 是小王,`X16` 是大王。座位:0 南(人)、1 东、2 北、3 西。

| 字段 | 说明 |
|---|---|
| `fmt` | `"80fen-record-2"` |
| `id` | 这一局的随机 id(用来去重) |
| `pid` / `nick` | 匿名玩家编号(随机生成、只存在本机)/ 玩家自填的昵称(可空) |
| `version` | 版本号文字,如 `80分 v0.7.38(测试版)` |
| `t` / `dur` | 打完的时刻(ISO)/ 从发牌到结算的秒数 |
| `human` | 人坐哪一家(现在恒为 0) |
| `no` | 整场里的第几局 |
| `seed` | 种子码(和设置里「本局种子码」相同,可用来重打这一局) |
| `replay` | 是否「重打本局 / 用种子开局」开出来的 |
| `redeals` | 这一局之前因低分 / 少主重新发了几次牌 |
| `dealer` / `firstTaker` | 开局时的庄家(-1 = 无庄盘、抢庄)/ 先拿牌的座位(`dealRound(seed, firstTaker)` 能重新发出同样的牌) |
| `declSeat` / `trump` | 最终庄家 / 主(`{suit, rank}`,`suit:null` 是无主) |
| `decl` | 叫牌过程:`[{seat, suit, strength, at}]`。`at` 是当时发到第几张,`strength` 1 单张、2 一对、3/4 小王对 / 大王对反;`re:1` 是加固,`a:1` 是托管替人亮的 |
| `kitty` / `buried` / `buryBy` | 原底牌 8 张 / 庄家扣下的 8 张 / 人坐庄时底是谁扣的(`h` 自己、`a` 托管;不是人坐庄时为 `null`) |
| `initialHands` | 扣底之后、开打之前四家的手牌(各 25 张) |
| `tricks` | 每一墩 `{plays:[{seat, cards, by?, hint?, u?}], winner, points}`,`plays` 按出牌顺序排。人那一家的每一手都带 `by`:`h` 自己出的,`a` 托管,`f` 没得选自动出的 |
| `levelsBefore` / `levelsAfter` | 两队级数(这一局前 / 后) |
| `defPoints` / `defendersWin` / `kittyPts` / `mult` | 闲家总分(含抠底)/ 闲家是否上台 / 底牌分 / 抠底倍数 |
| `rules` | 规则设置(造反、拖拉机跟牌、速通、关卡等) |
| `engines` | 四个座位的 AI 引擎版本(`latest` = 内置最新版;人那一家的只在托管时生效) |
| `coach` | 教练失误反馈灵敏度(`off` = 教练关) |
| `undos` / `autoTricks` | 本局悔牌次数 / 托管替人出的墩数 |
| `partial` / `stage` / `tricksDone` | **只有残局才有**。`stage` 是停在哪个阶段:`finalDecl` 亮主等待、`lowrebel` 造反、`kitty` 扣底、`play` 出牌;`tricksDone` 是已经收掉几墩。残局的 `tricks` 只有收掉的墩,`defPoints` 是到那时为止的墩上分,没有 `levelsAfter` / `defendersWin` / `kittyPts` / `mult`。开打前离开的没有 `initialHands` / `buried`,手牌用 `dealRound(seed, firstTaker)` 重发 |
